# Commits without an issue: 2026-11

## Declare the navisworks MCP server in .mcp.json (2026-11-03)

**What was asked.** "Update .mcp.json in the repos whose MCP servers are not what is needed to develop
code", then "commit that little changes without a issue link". The user skipped the reviews for this
change.

**What was done.**
- `.mcp.json` gains `navisworks`: `node MCP_Client/server/index.js`, type `stdio`. The `qmd` entry is
  unchanged.
- `.claude/settings.local.json`, which is tracked here, adds `navisworks` to `enabledMcpjsonServers`.
- [Connect an agent](../../workflows/connect-an-agent.md) step 2 no longer asks for `claude mcp add`
  inside this repo. `npm install` in `MCP_Client/server` is still needed once on each checkout.

**Decisions, with reasons**
- The entry is project-level, so it works from any checkout. **Rejected:** a user-level registration
  only, because it does not reach other machines.
- The path is relative with no machine value, because Claude Code starts a project server with the
  project as its working directory. **Rejected:** an absolute or drive-letter path, which breaks in any
  other checkout location.
- The entry is also listed in the tracked settings file, because a repo that lists only `qmd` in
  `enabledMcpjsonServers` would not enable the new server.

**Verified.** The coordinator's proof command ran only `initialize` and `tools/list` over stdio:
`qmd: OK, http server reachable`, `navisworks: OK, 15 tools`, exit 0. **Not verified:** that Navisworks
is reachable through the entry. The proof never touches the host application.
